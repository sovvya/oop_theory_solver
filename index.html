1. Принципы ООП, класс, this
Принципы ООП, их суть. Определение класса. Объект. Сокрытие информации. Отличие член-функций от обычных. Типы доступа. Указатель this.

Принципы ООП:

  1. Инкапсуляция — объединение данных и методов их обработки в одном классе + защита данных от прямого доступа извне (сокрытие).
  2. Наследование — создание нового класса (потомка) на базе существующего с перенятием его свойств и методов.
  3. Полиморфизм — один интерфейс и множество реализаций (перегрузка функций/операций, виртуальные методы).

Класс — пользовательский структурированный тип данных, объединяющий член-данные и член-функции (методы).

Объект — конкретный экземпляр (переменная) типа класс в памяти.

Сокрытие информации — помещение данных в раздел private, чтобы доступ к ним извне был возможен только через public-методы.

Отличие методов от обычных функций:

  • Объявляются внутри класса.
  • Имеют прямой доступ ко всем членам класса (включая private).
  • Вызываются для конкретного объекта через . или ->.
  • Имеют неявный указатель this.

Типы доступа:

  • private (закрытый, по умолчанию) — доступ только методам самого класса и friend-функциям/классам.
  • protected (защищенный) — доступ методам самого класса, friend и классам-наследникам.
  • public (открытый) — доступ из любого места программы (в т.ч. в main).

Указатель this — константный указатель (Class* const this), который неявно передается в любой нестатический метод и хранит адрес объекта, для которого вызван метод.

2. Методы, операция ::, внутри/вне
Чем член-функции отличаются от обычных. Операция ::. Отличие функций внутри класса от определенных вне класса.

Отличие член-функций от обычных: объявлены внутри класса; имеют доступ к private-полям; вызываются через объект; содержат неявный указатель this.

Операция :: (разрешения области видимости) — указывает компилятору, какому классу принадлежит метод или статическое поле при их определении или вызове вне класса (Class::Method()).

Внутри класса vs Вне класса:

  • Методы, определенные внутри класса, автоматически считаются встраиваемыми (inline) — компилятор подставляет их код прямо в место вызова (для коротких функций без циклов).
  • Методы, определенные вне класса (через ::), компилируются как обычные функции с передачей управления через стек (если явно не написать inline).
3. Конструкторы и деструкторы
Конструкторы и деструкторы. Назначение и особенности конструктора. Деструктор и его особенности.

Конструктор — спец. метод для автоматической инициализации член-данных объекта при его создании (и выделения памяти).

Особенности конструктора:

  1. Имя совпадает с именем класса.
  2. Не возвращает значения (даже void).
  3. Вызывается автоматически при создании объекта.
  4. Может иметь аргументы (и значения по умолчанию), может быть перегружен.

Деструктор — спец. метод для освобождения ресурсов (динамической памяти) перед уничтожением объекта.

Особенности деструктора:

  1. Имя: ~ИмяКласса().
  2. Не возвращает значения (даже void).
  3. Всегда не имеет аргументов.
  4. Не может быть перегружен (всегда один в классе).
  5. Вызывается автоматически при выходе объекта из области видимости или при delete.
4. Конструктор копирования vs =
Конструктор копирования. Когда необходим и почему. Чем отличается от перегрузки операции =.

Конструктор копирования A(const A& other) — создает новый объект, копируя данные из существующего объекта того же класса. Вызывается при: A b = a;, передаче объекта в функцию по значению, возврате объекта из функции по значению.

Когда необходим и почему: обязателен, если член-данные класса находятся в динамической памяти (есть указатели). Иначе конструктор по умолчанию сделает побитовое (поверхностное) копирование: указатели двух объектов будут ссылаться на одну и ту же память. Изменение одного испортит другой, а деструкторы вызовут ошибку при двойном delete[] одной памяти.

Отличие от операции =:

  1. Конструктор копирования создает новый объект, а = изменяет уже существующий.
  2. В операции = нужна проверка на самоприсваивание (this == &other) и очистка старой памяти (delete[]), а в конструкторе копирования старой памяти еще нет.
  3. Операция = возвращает *this по ссылке, а конструктор ничего не возвращает.
5. Правила перегрузки. + и +=
Перегрузка операций. Правила перегрузки. Перегрузки + и +=. Чем отличается + от +=.

Правила перегрузки операций:

  1. Хотя бы один операнд должен быть объектом класса (нельзя перегружать для встроенных типов).
  2. Нельзя создавать новые знаки операций (например, ~=).
  3. Нельзя менять приоритет, ассоциативность и арность (местность) операции.
  4. Нельзя перегружать: ., .*, ::, ?:, sizeof.
  5. Операции =, [], (), -> перегружаются только как методы класса.
  6. Как метод класса: унарная — 0 аргументов, бинарная — 1 аргумент. Как friend: унарная — 1 аргумент, бинарная — 2 аргумента.

Отличие + от +=:

  • + не меняет операнды, создает внутри новый локальный объект с суммой и возвращает его по значению: A operator+(const A& b) const;
  • += изменяет левый операнд (текущий объект *this) и возвращает его по ссылке: A& operator+=(const A& b);
6. Перегрузка операций [] и ()
Правила перегрузки операций. Перегрузка операций [], ().

Правила перегрузки — см. вопрос 5.

Операция индексации []:

  • Перегружается только как нестатический метод класса.
  • Имеет ровно 1 аргумент (индекс).
  • Возвращает ссылку на элемент (T& operator[](int i)), чтобы объект можно было ставить и слева от знака присваивания (a[0] = 5;).

Операция вызова функции ():

  • Перегружается только как нестатический метод класса.
  • Может принимать любое количество аргументов (от 0 и более) любых типов и возвращать любой тип. Используется для функторов, выделения подстроки s(i, len) или двумерной индексации m(i, j).
7. Перегрузка (тип) и ++
Правила перегрузки операций. Особенности перегрузки операции (тип). Перегрузка операции ++.

Правила перегрузки — см. вопрос 5.

Особенности операции приведения типа operator тип():

  1. Перегружается только как метод класса.
  2. Не имеет аргументов.
  3. Перед словом operator не пишется тип возвращаемого значения (само имя типа и является возвращаемым типом).
  4. Обязательно содержит return значения этого типа.
operator double() const { return r; }

Перегрузка инкремента ++:

  • Префиксная (++a): без аргументов. Изменяет *this и возвращает ссылку на него: 
    A& operator++() { a++; return *this; }
  • Постфиксная (a++): имеет фиктивный аргумент int. Сохраняет копию, изменяет *this, возвращает старую копию по значению: 
    A operator++(int) { A t(*this); a++; return t; }
8. Перегрузка операции =
Правила перегрузки операций. Перегрузка операции =. Когда необходимо перегружать =. Отличие конструктора копирования от =.

Правила перегрузки — см. вопрос 5. Отличие от конструктора копирования — см. вопрос 4.

Когда необходимо перегружать =: обязательно в классах, где член-данные размещаются в динамической памяти (есть указатели).

Схема перегрузки = (только как метод класса):

Array& Array::operator=(const Array& other) {
  if (this == &other) return *this; // 1. Самоприсваивание
  delete[] arr;                     // 2. Удаление старой памяти
  n = other.n;
  arr = new int[n];                 // 3. Новая память
  for(int i=0; i<n; i++) arr[i] = other.arr[i];
  return *this;                     // 4. Возврат по ссылке
}
9. Дружественность, потоки << и >>
Дружественность. Что может быть другом класса. Перегрузка >> и <<. Общее и разница. Можно ли как методы класса? Обязательна ли ссылка?

Дружественность (friend) — механизм, дающий внешней функции или чужому классу доступ к private и protected членам данного класса. У friend-функций нет указателя this.

Другом класса может быть: 1) обычная глобальная функция; 2) метод другого класса; 3) другой класс целиком.

Общее у << и >>: перегружаются как friend-функции с 2 аргументами; 1-й аргумент и возвращаемое значение — ссылка на поток.

Разница между << и >>:

  • В << поток типа ostream&, а второй аргумент (объект) передается по константной ссылке (const A&), т.к. не меняется.
  • В >> поток типа istream&, а объект передается по неконстантной ссылке (A&), т.к. в него записываются данные.

Можно ли перегрузить как методы класса? Нет, нельзя. В методе класса левым операндом всегда является объект нашего класса (через this), тогда пришлось бы писать obj << cout. Чтобы слева стоял поток cout << obj, функция должна быть внешней (friend).

Обязательна ли ссылка? Да, обязательно. Объекты потоков istream/ostream запрещено копировать (конструктор копирования закрыт) + ссылка нужна для цепочек cout << a << b и изменения объекта при вводе >>.

10. Массивы объектов
Массивы объектов. Какие конструкторы для статических объектов. Можно ли явно инициализировать динамический массив. Как работают конструктор и деструктор массива.

Инициализация статического массива объектов:

  • Без списка инициализации (A arr[5];) — вызывается только конструктор по умолчанию.
  • Со списком инициализации (A arr[2] = { A(1), A(2,3) };) — можно использовать любые конструкторы (в т.ч. разные для разных элементов).

Динамический массив (new A[n]): явно инициализировать параметрами нельзя — для всех элементов всегда вызывается только конструктор по умолчанию.

Работа конструктора для массива: вызывается для каждого элемента по порядку возрастания индексов от 0 до n-1.

Работа деструктора для массива: вызывается для каждого элемента в обратном порядке (от n-1 до 0) при выходе из области видимости или при вызове delete[].

11. Агрегированные классы (указатель)
Агрегированные классы. Как определить конструктор, если член-данное – указатель на объект другого класса? Как использовать private данные используемого класса.

Агрегированный класс — класс, содержащий в качестве своих член-данных объекты или указатели на объекты другого (используемого) класса.

Конструктор, если член-данное — указатель (A* ptr; в классе B): конструктор класса A сам не вызовется. Нужно в конструкторе класса B явно выделить память через new и вызвать конструктор класса A:

B::B(int x) {
  ptr = new A(x);
}

Доступ к private-данным используемого класса A:

  1. Через открытые (public) методы класса A (геттеры/сеттеры).
  2. Объявить класс B (или его методы) дружественным (friend class B;) внутри класса A.
12. Агрегированные классы (private)
Агрегированные классы. Каким образом агрегированный класс может использовать член-данные используемого класса из части private.

Агрегированный класс — класс, член-данными которого являются объекты (или указатели на объекты) другого класса.

Если член-данное является обычным объектом (A obj; внутри B), его конструктор вызывается через список инициализации конструктора B: B::B(int x) : obj(x) {}.

Использование private член-данных используемого класса A: агрегация не дает прав доступа к private части класса A. Доступ возможен только 2 путями:

  1. Через public-методы самого используемого класса A.
  2. Если класс A объявит агрегированный класс B своим другом (friend class B;).
13. Функции- и классы-шаблоны
Функции- и классы-шаблоны. Порожденная функция. Использование шаблонов. Работа компилятора.

Функция-шаблон — параметризованное описание функции, где типы аргументов и возвращаемого значения заданы обобщенным параметром template <class T>.

Класс-шаблон — параметризованное описание класса, в котором типы член-данных, а также типы аргументов и возвращаемых значений методов заданы параметром шаблона T.

Порожденная функция — конкретная функция, сгенерированная компилятором из шаблона путем подстановки конкретного типа вместо параметра T.

Использование: для функции-шаблона тип определяется автоматически по аргументам (Swap(a, b);). Для класса-шаблона тип обязательно указывается явно в угловых скобках: Stack<int> s;.

Работа компилятора: сам шаблон не компилируется в машинный код. При встрече вызова функции компилятор сначала ищет обычную подходящую функцию. Если ее нет — подставляет конкретный тип в шаблон и генерирует (компилирует) порожденную функцию для этого типа.

14. Статические член-данные
Статические член-данные: объявление, отличие от обычных, инициализация, влияние типа доступа, изменение и доступ в main.

Объявление: внутри класса с ключевым словом static (static int count;).

Отличие от обычных член-данных: создается в единственном экземпляре на весь класс (общее для всех объектов) и существует в памяти с начала работы программы, даже если не создано ни одного объекта.

Инициализация и влияние типа доступа: обязательно инициализируется вне класса (в глобальной области) через :: без слова static: int A::count = 0;. Тип доступа (private/public) никак не влияет на инициализацию.

Доступ и изменение в main:

  • Если поле public — его можно читать и менять в main напрямую через имя класса A::count = 5; или через объект obj.count = 5;.
  • Если поле private — напрямую в main обратиться нельзя, доступ возможен только через public-методы класса.
15. Статические методы класса
Статические методы класса: как объявляются, назначение, как определяются вне класса, особенности.

Объявление: внутри класса со словом static: static int GetCount();.

Назначение: работа со статическими член-данными класса и выполнение общих действий, не требующих конкретного объекта.

Определение вне класса: через имя класса и ::, но без слова static:

int A::GetCount() { return count; }

Особенности статических методов:

  1. Не имеют указателя this.
  2. Могут напрямую обращаться только к статическим членам класса (к обычным полям напрямую обращаться не могут).
  3. Если метод public, его можно вызвать в main без объекта через имя класса: A::GetCount(); (или через объект obj.GetCount();). Если private — вызвать в main нельзя.
  4. Не могут быть const или virtual.
